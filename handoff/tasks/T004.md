# T004 — Anchored fade encoder (Family 4) for ZN-E010

Why: every run underpredicts long-life cells; the degradation encoder only pools per-cycle features linearly
(mean, last, last-first -> Linear). With a linear inter_summary, adding [h_t, h_t - h_1] before pooling is redundant
(mean(h_t - h_1) = mean - h_1). The new mechanism is a NON-LINEAR per-cycle fade encoder on the anchored pair,
applied before masked pooling (architecture.md §2.2 Anchor / Reference Comparator).

Add class `AnchoredFadeResConvMaskedSummary(ResidualConvMaskedSummary)` in `train.py`:
- `__init__(d_model=64, residual_layers=2, d_ff=64, mlp_layers=0, summary_mode="mean_last_delta", dropout=0.0,
  activation="gelu", fade_hidden=64)`. Reuse the parent's shared ResConv curve encoder (cycle_stem + residual_blocks +
  pool) unchanged. When activation == "gelu", the parent's cycle_stem ReLUs must be GELU (rebuild cycle_stem with the
  same conv shapes; ResidualCurveBlock internals unchanged), and readout_activation uses F.gelu (as in T003).
- New `fade_encoder`: per cycle u_t = [h_t, h_t - h_1] (h_1 = features of cycle index 0) -> Linear(2*d_model -> fade_hidden)
  -> activation -> Linear(fade_hidden -> d_model) -> g_t, plus residual g_t = g_t + h_t. Then multiply by mask.
- Override the pooling input: the parent forward computes masked mean / last (at mask.sum()-1) / last-first on the
  curve features; here that same pooling (reuse the parent code path, e.g. by overriding a hook such as
  `encode_cycle_states(curves, mask)` that the parent forward calls; default hook = encode_curve_features) must act on g_t.
  Parent default behaviour must stay byte-for-byte identical (same outputs/state_dict for ZN-E005 config).
- `diagnostic_modules()`: cycle_stem, residual_blocks, fade_encoder, inter_summary, (inter_mlp if non-empty), head.
- `build_model`: variant "anchored_fade_resconv_masked_summary" with d_model, residual_layers, d_ff, mlp_layers,
  summary_mode, dropout, activation, fade_hidden.
Tests (tracked: `git add -f tests/test_anchored_fade.py`): padding invariance; cycle-1 dependence (changing cycle 0
changes output, changing a padded cycle does not); ZN-E005 config unchanged vs previous code (same seed outputs);
finite forward [2,100,3,300]; print params. Run each command separately (no && chains).
